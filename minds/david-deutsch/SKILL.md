# Purpose

This skill asks which explanation is best: which one accounts for the facts in a way that is hard to vary without losing its explanatory power. It treats progress as error correction, holds every belief open to criticism, and approaches problems as soluble given the right knowledge. This is a framework derived from Deutsch's books and talks, which build explicitly on Karl Popper. It does not simulate or speak for David Deutsch.

# When to Use

- Several competing explanations for why something is happening
- Strategies that depend on a theory of why customers or markets behave as they do
- Organizations that repeat errors because they can't detect or correct them
- Problems where pessimism ("it can't be solved") is shaping the options

Do not use for:

- Quick operational choices where explanation is not the bottleneck

# Core Questions

- **What is the best explanation, and is it hard to vary?** (MINDS summary, not a quotation)
- Would this explanation survive if its details were changed arbitrarily?
- What mechanism lets us find and fix our errors?
- Are we treating this problem as soluble, or as a fixed limit?

# Documented Principles

| ID | Principle (MINDS' wording) | Provenance | Source |
|---|---|---|---|
| P1 | Good explanations are hard to vary: every detail plays a functional role, so changing it would ruin the explanation. Easy-to-vary explanations could explain anything and so explain nothing. | DOCUMENTED | S1, S3 |
| P2 | Testability alone is insufficient. An explanation can be testable yet bad. What matters is explanatory reach and resistance to arbitrary variation. | DOCUMENTED | S1 |
| P3 | Progress comes from error correction: conjecture, criticism, and improvement. Institutions and traditions that support criticism allow sustained progress. | DOCUMENTED | S1 |
| P4 | Fallibilism: all knowledge is conjectural and may contain errors, so the aim is not certainty but better explanations. | DOCUMENTED | S1, S2 |
| P5 | Problems are inevitable, and problems are soluble. Failure to solve one reflects missing knowledge, not a law of nature (unless physics forbids it). | DOCUMENTED | S1 |
| P6 | The agent must rank competing explanations by how hard each is to vary, not by how many facts each can accommodate. | OPERATIONALIZED | P1, P2 |

# Analytical Procedure

1. **List the rival explanations.** Include the one the team currently holds.
2. **Hard to vary (P1, P6).** For each explanation, ask whether its details could be swapped and it would still "explain" the data. If so, it is weak.
3. **Reach (P2).** Which explanation also accounts for other observations it wasn't designed for?
4. **Criticism (P3, P4).** Which parts of the best explanation have been exposed to real criticism, and which were only assumed?
5. **Error-correction machinery (P3).** How would the organization find out if it were wrong? How fast?
6. **Solubility (P5).** Is any option being dismissed as impossible without an actual constraint? What knowledge is missing?

# What This Framework Pays Attention To

- Quality of explanation over quantity of evidence
- Error correction and criticism
- Optimism about solving problems given knowledge

# What This Framework May Underweight

- Probabilistic and Bayesian framings, which the framework is skeptical of (see Duke, Kahneman)
- Short-term operational constraints
- Irreducible randomness and tail risk (see Taleb)

# Questions to Ask

- Could our explanation survive if we changed its key details? If so, is it really explaining anything?
- What else does the best explanation predict that we haven't checked?
- How does this organization learn it is wrong?
- What would we need to know to solve the problem we are calling impossible?
